# Z Journey Hub – Server

Express + Mongoose API for Mission 5 Phase 2.

One server, one shared `Station` model, and **one route file + one controller file per screen**. Each person writes the backend for their own screen.

## Database status

- The shared database `z-journey-hub` is set up on **MongoDB Atlas**.
- Everyone has been invited to the Atlas project as **Project Owner**. Check your email and accept the invite.
- **1 station** is in the database for now (Z Station 1, placeholder Christchurch data). More will be added later.
- To see the data in Atlas: **Clusters → Browse Collections → z-journey-hub → stations**.

## What you need

- **Node.js 18 or newer.** Check with `node -v`. If it's missing, install the LTS version from <https://nodejs.org>.
- **A MongoDB Atlas login** – accept the team invite (see below).
- Optional: **MongoDB Compass** for looking at the data, and **Postman** for testing endpoints.

`npm install` (Step 1) installs everything else from `package.json`:

| Package | What it does |
| --- | --- |
| `express` | The web server and routes |
| `mongoose` | Talks to MongoDB, defines the `Station` schema |
| `cors` | Lets the React app (different port) call this API |
| `dotenv` | Reads `MONGO_URI` and `PORT` from `.env` |
| `nodemon` (dev) | Restarts the server when you save a file (`npm run dev`) |

You don't need to install any of these one by one.

## Getting started

Do these once, in order.

### Step 1 – Get the code

```powershell
git pull
cd server
npm install
```

### Step 2 – Make your database login

1. Accept the Atlas invite from your email.
2. In Atlas, go to **Security → Database Access → Add New Database User**.
3. Choose a username, click **Autogenerate Secure Password**, and copy the password somewhere safe.
4. Click **Add User**.

> Use the autogenerated password. Symbols like `@` or `#` break the connection string.

### Step 3 – Get your connection string

1. In Atlas, go to **Clusters → Connect → Drivers**.
2. Copy the string. It looks like this:

   ```text
   mongodb+srv://<user>:<password>@cluster0.abcde.mongodb.net/
   ```

### Step 4 – Make your `.env` file

1. In the `server` folder, copy the example file:

   ```powershell
   Copy-Item .env.example .env
   ```

2. Open `.env` and change the first line to your connection string:
   - Keep `MONGO_URI=` at the start.
   - Put your username and password in place of `<user>` and `<password>` (remove the `< >`).
   - Add `z-journey-hub` after `.net/`.

   ```text
   MONGO_URI=mongodb+srv://<user>:<password>@<cluster>.mongodb.net/z-journey-hub
   PORT=5000
   ```

> `.env` must sit in the `server` folder, next to `server.js` – not inside `config/`.
> **Never commit `.env`.** It holds your password.

### Step 5 – Start the server

```powershell
npm run dev
```

You should see:

```text
MongoDB connected: z-journey-hub
Server running on http://localhost:5000
```

Then open <http://localhost:5000/api/health> in your browser. You should see `{"status":"ok"}`.

### If it doesn't work

| Error | Fix |
| --- | --- |
| `Could not read package.json` | You're in the wrong folder. `cd` into `server` first. |
| `MONGO_URI is missing` or `got "undefined"` | `.env` is in the wrong folder, or the line doesn't start with `MONGO_URI=`. |
| `bad auth` | Wrong username or password in `.env`. |
| `ENOTFOUND` | The cluster part of the connection string is wrong. Copy it again from Atlas. |
| Timeout | Your IP isn't allowed. Ask Sarita to check **Network Access** in Atlas. |

## Writing your backend

Your route and controller files already exist with your name on them. They are empty – you write everything inside them. The empty `router` in your route file is only there so the server starts; `server.js` already connects your file, so you don't need to touch it.

1. Pull `main`, then make your branch: `feature/<screen-name>` (e.g. `feature/station-details`).
2. Test your query in MongoDB Compass first, then in the controller, then in the browser or Postman.
3. Push daily, open a PR into `main`, and review other PRs before the 2pm stand-up.

Until you write your route, your endpoint returns `{ "message": "Route not found" }` (404). That's expected.

### Team rules

- **Only edit your own route + controller file.** Don't touch `server.js` or `models/Station.js` without a team PR.
- Need a new field? Raise it at stand-up. Then `Station.js` + `stations.json` change in one PR.
- Only use `npm run seed -- --reset` after asking the team – it deletes every station first.
- Want to experiment? Use `z-journey-hub-<yourname>` as the database name in your `.env`.
- Never commit `.env`. Run `git status` before every commit and check it's not listed.

## Adding and updating stations

Everyone can add stations and change prices. There are two ways.

### Seed file – for changes the whole team should keep

1. Pull `main` first, so you have everyone's latest stations.
2. Edit [seed/stations.json](seed/stations.json). To add a station, copy a `{ ... }` block, put a comma between blocks, and change the values:

   ```json
   {
     "name": "Z Station 2",
     "address": "45 Riccarton Road",
     "city": "Christchurch",
     "location": { "type": "Point", "coordinates": [172.6, -43.53] },
     "hours": { "open24_7": false, "closesAt": "22:00" },
     "prices": { "z91": 2.65, "zxPremium": 2.85, "diesel": null },
     "services": ["ev"]
   }
   ```

3. Load it into Atlas:

   ```powershell
   npm run seed
   ```

   You should see `Done: 1 added, 1 updated`.
4. Commit `stations.json` in a PR, so the team gets your change.

How `npm run seed` works:

- Stations are matched by **name**. Same name = updated, new name = added.
- It **never deletes** anything. To remove a station, delete it in Atlas (**Browse Collections**) and from `stations.json`.
- `npm run seed -- --reset` deletes every station first, then loads the file. Ask the team before using it.

Rules for the values:

- `coordinates` are **longitude first**, then latitude.
- Prices are numbers (`2.69`, no `$`). Use `null` (no quotes) for "Not listed".
- `services` can only be `carwash`, `ev`, `lpg`, `coffee`.
- `closesAt` is a 24-hour time like `"22:00"`, or `null` if `open24_7` is `true`.

### CLI – for a quick price change

```powershell
npm run cli price 1 z91 2.59
```

This changes Atlas straight away, but **not** `stations.json`. The next `npm run seed` puts the file's price back. Good for testing and demos.

## Endpoints

`lng` and `lat` are optional on all of them. They default to Christchurch city centre.

| Screen | Owner | Endpoint |
| --- | --- | --- |
| Journey Hub | Cajun | `GET /api/hub/nearby?fuel=z91&km=10` |
| Station results | Anna | `GET /api/results?fuel=z91&km=10&services=carwash` |
| Station details | Shubhada | `GET /api/stations/:id` |
| Compare prices | Sarita | `GET /api/compare/options?fuel=z91` and `GET /api/compare?ids=a,b&fuel=z91` |

- `fuel`: `z91` | `zxPremium` | `diesel`
- `km`: `5` | `10` | `25` | `50`
- `services`: comma list of `carwash`, `ev`, `lpg`, `coffee`
- Price `null` means "Not listed"
- Errors always come back as `{ "message": "..." }`

## Team CLI

Check and change station data from the terminal. Run these from the `server` folder:

```powershell
npm run cli help                  # list all commands
npm run cli list diesel           # all stations, cheapest diesel first
npm run cli show 1                # full details for Z Station 1
npm run cli find carwash          # stations with a car wash
npm run cli near 10 zxPremium     # within 10 km of Christchurch centre
npm run cli price 1 z91 2.69      # change a price (use null for Not listed)
```

Handy for testing: change a price with the CLI, refresh the app, and the new price shows up.
